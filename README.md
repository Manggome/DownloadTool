# 링크세이버 (LinkSaver)

링크만 붙여넣으면 사진·영상을 폰 갤러리에 저장하는 안드로이드 앱.

**[📥 최신 APK 받기](https://github.com/Manggome/DownloadTool/releases/latest/download/LinkSaver.apk)** — 폰에서 이 링크를 누르면 바로 설치됩니다.

- 추출 엔진: **yt-dlp** (파이썬 런타임 + ffmpeg 번들 내장)
- UI: Kotlin + Jetpack Compose (Material 3)
- 최소 안드로이드 7.0 (API 24)

---

## 무엇을 받을 수 있나

받을 수 있는 사이트는 내장된 yt-dlp 엔진이 결정합니다. 엔진이 공식 추출기를 가진 곳이면 그대로 시도하고, 없는 곳은 실패로 표시됩니다.

| 대상 | 상태 | 비고 |
|---|---|---|
| 인스타그램 게시물 (사진·영상) | ✅ | 여러 장이면 **받을 것만 골라서** 저장 |
| 인스타그램 릴스 | ✅ | |
| 인스타그램 스토리·하이라이트 | ✅ | **로그인 필요** |
| X(트위터) 영상·GIF·이미지 | ✅ | 이미지는 원본급(최대 4096px) |
| X 연령제한 게시물 | ✅ | **로그인 필요** — 로그아웃 상태에선 서버가 내용을 아예 주지 않음 |
| 틱톡 | ⚠️ | 403이 나는 경우가 있어 폴백 경로로 재시도 |
| 그 외 (트위치·사운드클라우드 등) | ⚠️ | 엔진이 지원하면 동작 |
| 비공개 계정 · 삭제된 게시물 | ❌ | 원리상 불가 |

## 주요 기능

**링크 하나로 시작**
앱에서 `공유 → 링크세이버` 를 누르거나, 링크를 복사한 뒤 앱을 열면 자동으로 채워집니다. 단축링크(`t.co`, `instagram.com/share/…`)는 리다이렉트를 따라가고, 추적 파라미터(`?igsh=`, `?t=`, `?s=`)는 떼어냅니다.

**여러 장인 게시물에서 골라 받기**
다운로드를 누르면 먼저 게시물 내용을 확인합니다. 미디어가 여러 개면 썸네일 격자가 뜨고, 원하는 것만 체크해서 받을 수 있습니다. 각 칸에 순번·사진/영상 구분·해상도 또는 재생시간이 표시됩니다. 내부적으로는 `--playlist-items` 로 선택 항목만 내려받습니다.

**화질 선택**
`최고 화질 / 720p / 오디오만(MP3)` 중에서 고르고, 마지막 선택이 기억됩니다.

**앱 내 로그인**
설정에서 X·인스타그램·틱톡 각각 공식 로그인 페이지를 앱 안에 띄워 세션 쿠키를 저장합니다. 비밀번호는 앱이 다루지 않습니다.

인스타는 기본적으로 **익명으로 먼저 시도**하고, 안 되는 것(스토리 등)만 로그인 세션으로 넘어갑니다. 세션을 쓸 때마다 계정에 흔적이 남고 "의심스러운 로그인" 경고가 올 수 있어서입니다. 설정에서 끌 수 있습니다.

**엔진 자동 최신화**
플랫폼이 내부 구조를 바꾸면 다운로드가 깨집니다. 앱은 첫 실행 시(그리고 3일마다) yt-dlp 최신판을 자동으로 받아둡니다. 번들된 엔진은 라이브러리 배포 시점 것이라 몇 달씩 뒤처지기 때문에 이 과정이 필요합니다.

**앱 자체 업데이트**
새 버전이 올라오면 앱이 알려주고, 받아서 설치까지 이어줍니다. 서명 키가 고정돼 있어 기존 앱을 지울 필요가 없습니다. 설정 → `앱 업데이트` 에서 직접 확인할 수도 있습니다.

**실패 원인 확인**
실패한 항목을 탭하면 엔진이 실제로 뱉은 오류 원문이 그대로 나옵니다. 한국어 요약만으로는 원인을 알 수 없는 경우가 많아 필요합니다. 폴백 경로가 여럿일 때는 경로별 사유가 각각 표시됩니다.

저장 위치:

- 사진 → `Pictures/LinkSaver`
- 영상 → `Movies/LinkSaver`
- 오디오 → `Music/LinkSaver`

## 문제 해결

**첫 실행이 느려요**
파이썬 런타임을 내부 저장소에 푸는 과정(5~20초)과 엔진 최신화가 겹칩니다. 한 번만 그렇습니다.

**갑자기 전부 실패해요**
설정 → `yt-dlp 엔진` → 업데이트. 앱 재설치 없이 엔진만 갱신됩니다.

**"로그인을 요구했습니다"**
익명 요청 제한에 걸린 상태입니다. 몇 분 뒤 재시도하거나 해당 플랫폼에 로그인하세요.

**되다가 갑자기 안 돼요**
IP 단위 요청 제한일 가능성이 높습니다. 수십 분 기다리면 풀립니다.

**계정 정지가 걱정됩니다**
자동화 도구로 세션을 쓰는 것은 각 플랫폼 약관 위반입니다. 실제로는 일시 차단이나 세션 무효화 선에서 멈추는 경우가 많지만, **주계정 대신 별도 계정**을 쓰시길 권합니다.

## 빌드

push 하면 GitHub Actions 가 자동으로 빌드해서 `latest` 릴리스를 갱신합니다.

- 서명 키는 `keystore/debug.jks` 로 저장소에 고정돼 있습니다. 없으면 CI 가 한 번 만들어 커밋합니다. 빌드마다 키가 바뀌면 덮어쓰기 설치가 안 되기 때문입니다.
- 정식 서명이 필요하면 [make-keystore 워크플로](../../actions/workflows/make-keystore.yml)로 키를 만들고 `KEYSTORE_B64` / `KEYSTORE_PASSWORD` / `KEY_ALIAS` / `KEY_PASSWORD` 시크릿을 등록하세요. 그러면 release 빌드가 나갑니다.
- 버전은 CI 실행번호로 매겨집니다 (`1.0.<run_number>`). 릴리스에 `latest.json` 이 함께 올라가고 앱이 이것과 자기 버전을 비교합니다.
- 빌드가 실패하면 원인이 실행 요약 페이지와 `ci-logs` 브랜치(`last-failure.txt`)에 자동으로 발행됩니다.

### 알아두면 도움되는 설계 결정

**사진은 엔진이 아니라 앱이 직접 받습니다.** yt-dlp 의 인스타 추출기는 사진을 `formats` 가 아니라 `thumbnails` 배열에만 담습니다. 그래서 사진 게시물은 포맷이 0개가 되고 `No video formats found` 로 끝납니다. 앱이 그 배열의 최고 화질 URL 을 꺼내 직접 내려받습니다.

**`--no-warnings` 를 쓰지 않습니다.** 틱톡은 모바일 API 실패를 경고로 처리한 뒤 웹페이지로 넘어갑니다. 경고를 숨기면 진짜 실패 사유가 사라지고 폴백 단계의 403 만 보입니다.

**조회 결과를 5분간 캐시합니다.** 링크 하나를 받는 동안 조회가 여러 번 일어나는데, 인스타는 요청 수에 민감해 뒤쪽 조회가 빈 응답을 받는 일이 잦습니다.

**틱톡 단축링크는 앱이 풀지 않습니다.** yt-dlp 의 `TikTokVMIE` 가 직접 처리합니다. 앱이 미리 풀면 `www` 없는 형태로 떨어져 오히려 인식이 깨집니다.
